# Audit và kế hoạch refactor gslide-web — 2026-09-24

**Mục tiêu:** Giảm độ khó bảo trì và chi phí render, giữ nguyên giao diện, hành vi hợp lệ và wire contract hiện có của FastAPI/Next.js trong từng đợt refactor.

**Phạm vi:** Toàn bộ mã nguồn trong `app`, `components`, `store`, `lib`, `utils`, `i18n`, cấu hình, kiểm thử, tài nguyên tĩnh và triển khai. Không audit mã của `gslide-api`, `node_modules`, `.next`, `.next-build`, `.git`. Thư mục `models` hiện rỗng. Đây là kế hoạch, chưa có thay đổi product code.

**Mức độ:** P0 = có khả năng lộ dữ liệu hoặc chèn HTML, cần xác nhận sớm; P1 = nút thắt kiến trúc hoặc rủi ro sai hành vi cao; P2 = chi phí bảo trì/hiệu năng đáng kể; P3 = dọn dẹp có điều kiện. Các P0 có thể đòi hỏi thay đổi hành vi đối với đầu vào không hợp lệ hoặc người chưa đăng nhập; không gộp chúng vào đợt refactor giữ nguyên contract nếu chưa chốt ngoại lệ.

## Kiến trúc hiện tại

```text
Next App Router
  layout → ClientRoot → FeatureFlagsProvider → I18nProvider → Redux Provider
  ├─ dashboard / upload / documents-preview / presentation / template-preview / custom-template / theme
  ├─ pdf-maker → Chromium phía gslide-api → PDF/PPTX
  └─ app/api/* (BFF, file/export/template/config)

Browser → services/api/* + một số fetch trực tiếp → /api/v1,/api/v2
        → proxy.ts → gslide-api (FastAPI)
Browser ↔ Redux: presentationGeneration, presentationGenUpload, userConfig, undoRedo
Template V2: API JSON → import/model → Konva editor; cùng JSON → HTML preview/export
```

Quy mô kiểm tra: 327 file nguồn TypeScript/TSX/MJS (~83,5 nghìn dòng vật lý), trong đó `app` 153, `components` 130, `store` 5, `lib` 23, `utils` 8, `i18n` 8; 71 file trong `public`; 32 file Node test và 8 Cypress component spec. Có 42 runtime dependencies, 11 dev dependencies. Đồ thị import tĩnh cho thấy hai vòng import **chỉ ở mức type**: `template-v2-text` ↔ `template-v2-text-editing`, `LayoutToolbar` ↔ `ContainerToolbarControls`; chưa thấy vòng runtime từ hai cặp này. Các điểm được import nhiều nhất là `i18n/provider.tsx` (75), `lib/utils.ts` (57), `components/slide-editor/types.ts` (39), `utils/api.ts` (22) và Redux presentation slice (19). Đây là số liệu định hướng review, không tự nó chứng minh lỗi hiệu năng.

Các điểm tích cực cần giữ: editor đã có culling theo viewport và memo cho node; autosave đã phân biệt thay đổi cấu trúc/slide; nhiều luồng stream có cleanup/retry; `knip`, TypeScript và kiểm tra i18n hiện qua. Kế hoạch không thay thế các cơ chế này một cách đồng loạt.

## Ranh giới phụ thuộc cần giữ

1. `gslide-api` sở hữu auth, generation, template, asset và export; `proxy.ts` và Next BFF phải giữ nguyên path `/api/v1`, `/api/v2`, `/app_data`, `/static`, `/pdf-maker`, cookie và status hiện có. Các đợt bảo mật F01/F02/F19 được đánh dấu ngoại lệ để xác nhận riêng.
2. `utils/api.ts` và `services/api/*` là nền của upload, dashboard, chat, template/theme, streaming. Đợt transport phải xong trước khi di chuyển caller; có thể refactor từng caller độc lập khi contract tests đã cố định.
3. `store/slices/presentationGeneration.ts` là dữ liệu cho autosave, streaming, chat, editor, export; thay đổi schema phải đi trước việc trích xuất logic của các consumer. Không đổi JSON backend và phân biệt V1/V2.
4. `components/slide-editor/types.ts`/import/model là nền cho toolbars/Konva và HTML export; tách model/import trước surface, sau đó so sánh preview/export.
5. `i18n` và design system là phụ thuộc chung; tránh sửa catalog/tokens trong cùng PR với thay đổi logic vì làm khó đối chiếu UI.

## Quy tắc thực hiện bổ sung

- Áp dụng skill `simplify` (skill đơn giản hóa code khả dụng trong môi trường này) cho phần code thay đổi ở **từng đợt**, theo ba lượt rà soát: tái sử dụng helper sẵn có, chất lượng/ranh giới state, và chi phí runtime/bộ nhớ. Chỉ đưa vào các chỉnh sửa có bằng chứng rõ ràng và giữ nguyên hành vi; tránh trừu tượng hóa chỉ để giảm số dòng. Đọc lại diff và chạy kiểm tra sát phạm vi sau lượt rà soát này.
- **Không tự động chạy `git commit`.** Sau mỗi đợt, để thay đổi ở trạng thái có thể xem diff và kiểm thử; chỉ tạo commit khi người dùng yêu cầu tường minh. Quy tắc này áp dụng cả khi một skill khác gợi ý commit như một bước mặc định.
- Giai đoạn hiện tại vẫn chỉ audit và lập kế hoạch. Việc thêm hai quy tắc trên không cho phép sửa product code trước khi người dùng yêu cầu triển khai một đợt cụ thể.

## Tình trạng kiểm tra tại thời điểm audit

- `npm run typecheck`: qua.
- `npm run deadcode`: qua, không có file/dependency manifest bị Knip báo theo cấu hình hiện tại.
- `npm run check:i18n-copy`: qua.
- `npm run lint`: qua với **15 warnings**, gồm 13 `no-img-element` và 2 `react-hooks/exhaustive-deps` (`GenerationStatusBar.tsx:244`, `usePresentationStreaming.ts:754`); ceiling hiện là 19.
- `npm run check` dừng ngay tại `npm test`: môi trường này chặn `child_process.spawn` (`EPERM`) của Node test runner. Chạy `node --test --experimental-test-isolation=none tests/*.test.mjs` được 222/226 subtest qua; 4 test `prompt-rewrite.test.mjs` vẫn thất bại vì chính file test dùng `spawnSync`, không có bằng chứng bốn hành vi sản phẩm bị lỗi.
- Chưa chạy Cypress và build trong audit này. Repo không chứa `gslide-api`/Chromium nên contract tích hợp và PDF/PPTX cuối cùng phải xác nhận trong CI/stack đầy đủ. `npm ls --depth=0` thấy ba package extraneous chỉ trong local `node_modules`; không kết luận lockfile sai.

**Quy tắc dừng từng đợt:** Nếu test contract/ảnh golden đổi ngoài phạm vi đã chốt, quay lại đợt đó và không tiếp tục sang consumer. Ghi số liệu render/save/export thực đo trước khi tuyên bố cải thiện hiệu năng. Không xóa mã V1, đổi URL/API JSON, đổi bản dịch hiển thị hoặc bật Strict Mode hàng loạt trong các đợt giữ nguyên hành vi.
